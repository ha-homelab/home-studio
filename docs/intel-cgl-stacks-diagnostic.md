# Intel CGL first-load stack diagnostic

This disposable push-only workflow uses exact signed source `7b7a896225aaf27fef26a135d654dfaddffe2c08`, verified native Firefox ESR 153.5.0 and one `macos-15-intel` host. It runs the original **two-cycle viewer-24 case**, including its original fixture, dimensions, lights, gestures, recovery, backend assertions, 30-second load limit and 180-second browser watchdog. It does not change the 77-lane release matrix. The wrapper labels both its outer receipt and original case `diagnosticOnly: true` / `acceptanceStatus: not-run`; a passing sampled case gives no release credit.

The exact source's five-gate ephemeral Intel preparation runs before browser installation. The observer also rejects any host that is not GitHub Actions, GitHub-hosted, `RUNNER_OS=macOS`, Python `darwin`, and `x86_64`. It waits for the existing startup checkpoint of the first main fragment draw, fingerprint `fnv1a32:c2019e3f` and length 49,740, at most 90 seconds. Draw events omit shader metadata, so the observer joins their program identity to its preceding link event. This exact fragment was recorded in the R19 Intel ESR viewer-24 primary receipt; the program ordinal itself is not fixed. It does not add a render, fence, state reply, delay, shader modification or browser-side observation. Asynchronous checkpoint delivery can lag the actual draw, so a missed cold window cannot be ruled out. Polling this local checkpoint file occurs once per second. An absent or changed fingerprint is recorded as missing evidence; it never triggers a substitute test.

At that checkpoint the observer verifies the original launched Firefox PID against WebDriver and parent PID, executable path and process start time. It independently samples that parent and at most two owned `plugin-container` descendants with the browser `tab` role, selected by the `ps` CPU estimate. Each target is revalidated immediately before launch. The read of command-line role tokens is restricted to verified descendants; arguments are discarded, not recorded. Stored process identities contain numeric fields, start time and executable basename only. Content selection is not a guarantee that the selected process hosts the opaque fixture frame; parent and content stacks are deliberately separate because earlier ARM content stacks showed IPC waits while the parent executed OpenGL work.

Each command is `/usr/bin/sample PID 10 10 -file OUTPUT`: ten seconds at a ten-millisecond interval, launched independently for up to three targets. Each command has a 60-second wall limit including symbolication; no permission escalation, alternate profiler or retry is attempted. Retained reports are capped at 8 MiB and command logs at 64 KiB per process (up to 24 MiB plus 192 KiB total). The observer checks limits every 250 ms and stops oversized output before retaining its bounded prefix. A partial report, nonzero exit, output limit or cleanup error remains visible as incomplete evidence. The original case always performs its own cleanup first; observer cleanup then stops and joins its own children without replacing the original result or exception. Full stack reports may include public browser/system binary paths and symbols; no environment or global command-line inventory is retained.

Sampling suspends threads and therefore perturbs execution. Sample start/finish timestamps include symbolication and are not the exact sampling interval. The original test may fail because of sampling overhead; preserve that failure. The output is for distinguishing compiler/liveness work from fragment interpretation or IPC waits, not for comparing performance or qualifying a release. Existing output is rejected rather than reused or overwritten. All source file hashes before/after, the original viewer function hash, generated observer wrapper, verified installation, preparation receipt, original case, startup events and bounded sample outputs are retained in the diagnostic artifact for 14 days.

Offline validation: `python3 scripts/test-intel-cgl-stacks.py`. These tests mock process discovery and sampling; they must not invoke `ps`, `sample`, `mdutil` or a browser. Pushing the explicitly named disposable branch starts one diagnostic job; this document is not authorization to push or dispatch it.
