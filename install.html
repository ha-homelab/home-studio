01 · KEEP YOUR EDITABLE SOURCE

Export your drawing

  1. Open Home studio. Draw your rooms and walls, add openings, and check each floor in Preview 3D.
  2. Choose Build & install and review any validation message. You can export an unfinished draft, but the compiler needs a valid project.
  3. Choose Export project.json. Move the downloaded file to a private folder you can find again.

Keep this JSON file when you build or install. It is the editable source for future geometry changes. Entity IDs can stay blank until you link devices inside Home Assistant.

02 · A COMPLETE LOCAL TOOLKIT

Download and open the toolkit

  1. Download the complete repository ZIP and extract it. Open the resulting home-studio-main folder.
  2. Open a terminal in that folder. You should see scripts, planner, and custom_components alongside README.md.
  3. Run python3 --version. If needed, install Python 3.10 or newer from python.org. The compiler and installer use the standard library; no pip install step is needed.

On Windows, your command may be py -3; use that wherever this guide says python3. Replace example paths with real paths on your computer, and put quotes around a path containing spaces. A downloaded website page by itself is not the complete toolkit.

03 · MAKE YOUR VIEWER AND PACKAGE

Build, then take a look

From the toolkit folder, run this command with the path to your exported project:

python3 scripts/build-planner-project.py --project /path/to/project.json --output dist/my-home --ha-package

The compiler writes your viewer and floor exports to dist/my-home, including home-floorplan.tar.gz for Home Assistant. Use an empty output folder or one created by an earlier build. Keep the editable project outside that output folder.

Preview the result with a local web server:

python3 -m http.server 8099 --bind 127.0.0.1 --directory dist/my-home

Open http://127.0.0.1:8099/, choose a floor, and check its layout. Keep the terminal open while viewing; press Ctrl+C when finished. This preview does not control devices.

Keep your home private. The generated viewer and archive contain your plan and any entity bindings. The server above is bound to your own computer. Do not upload a real home build to a public repository or website.

04 · CHOOSE YOUR FILE ACCESS

Install into the right config folder

If Python runs on a host with direct access to Home Assistant's config directory, use the local installer below. This is the directory containing configuration.yaml; for a container it is the host directory mounted as /config.

If you use Home Assistant OS and only access HA through a browser or file share, follow the Samba copy route instead. The installer expects a local filesystem path, not an HA address or token.

First, validate without changing files

python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config /path/to/ha/config --dry-run

Check the printed destination and site name. The config directory must already exist, and its path must not pass through a symlink. A successful dry run creates or changes no files.

Then install

python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config /path/to/ha/config

The installer places the complete component under custom_components/home_floorplan. It does not edit YAML, restart HA, or change saved placements. Continue to enable the panel.

Already installed? An existing component is protected by default. Follow Updates and backups: validate with --replace, stop Home Assistant Core, then perform the replacement with the same flag.

Home Assistant OS: validate locally, copy over Samba

  1. Build on your computer using the steps above. Create an empty folder named ha-transfer inside the toolkit folder.
  2. Validate and unpack through the installer into that local folder: 
    python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config ha-transfer --dry-run
python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config ha-transfer

    This prepares files for transfer; it has not installed anything on your HA machine.

  3. Use the official Samba share instructions to open HA's config share in your computer's file manager. Use your own share credentials there.
  4. Before replacing an existing component, back up HA and stop Core through a console or management connection that can start it again. On the HAOS command line, use ha core stop. Keep that connection available.
  5. If config/custom_components/home_floorplan exists, move that entire old folder into a dated folder under config/.home-studio-backups. Keep the backup outside custom_components.
  6. Copy the complete ha-transfer/custom_components/home_floorplan folder to config/custom_components/home_floorplan on the share. Create custom_components if needed. Do not merge new files into the old component; wait for the entire copy to finish.

Leave .storage and unrelated components alone. If a copy fails, remove the incomplete new component and put the retained old folder back before starting Core. File-manager transfers do not have the local installer's automatic rollback.

05 · ONE YAML ENTRY

Enable 3D Home

Open your HA configuration.yaml. Add this entry at the top level, with no spaces before its name:

home_floorplan: {}

If home_floorplan: already exists, keep that entry and merge any changes there; do not add a second key. Check the configuration before starting or restarting Core. HAOS provides ha core check; a running HA also has a YAML configuration check in its tools. See the official configuration-check instructions.

After a successful check, start Core if you stopped it, or restart it if it is running. On the HAOS command line use ha core start or ha core restart, respectively. Other installations use their normal host or container controls.

Sign in to Home Assistant with an administrator account, refresh the browser, and open 3D Home in the sidebar. The panel uses your existing HA login.

06 · CONNECT YOUR OWN ENTITIES

Make the plan respond to your home

  1. In 3D Home, choose Edit layout, then Plan & placement.
  2. Select or place an item and set its Home Assistant entity_id to an actual entity from your HA installation. Use the suggested entities where available.
  3. Wait for Saved in Home Assistant before leaving the panel. These saved placements belong to HA, separately from the hosted editor's browser draft.
  4. Return to Home view. Check a known light or switch with an intentional click and confirm its state in HA.

Entity IDs entered in the browser editor become initial mappings; the editor itself never controls those devices. Missing or unavailable entities remain disabled. The generic panel supports its documented entity controls; placing a TV or sensor does not activate specialized TV capture, camera, or RF sensing adapters.

Updates and backups

Keep your project JSON and project ID, make a Home Assistant backup, then build the revised package. Validate the replacement while HA is still available:

python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config /path/to/ha/config --replace --dry-run

Stop Home Assistant Core using your host or console connection, then run:

python3 scripts/install-home-assistant.py dist/my-home/home-floorplan.tar.gz --config /path/to/ha/config --replace

Keep the printed timestamped backup path under .home-studio-backups. The installer retains the old component and rolls back if the directory swap fails. Check configuration and start Core again. Saved .storage data is preserved; if changed rooms make an old layout incompatible, follow the panel's recovery prompts.

To restore a retained component, stop Core, move the current component aside, and move the backup folder back to custom_components/home_floorplan. Check configuration before starting. This restores component files, not the whole HA installation or an earlier copy of saved placements.

If something goes wrong

Python or a script cannot be found

Check the Python version and your terminal's current folder. Run the commands from the extracted toolkit folder that contains scripts. On Windows, try py -3 --version. The browser cannot run the Python commands.

The compiler rejects my project or output folder

Read the field named in the error and correct it in the editor. Export again. An unrelated nonempty output directory is protected; choose a new empty output path. Do not put the source JSON inside the replaceable output folder.

The installer rejects a path or archive

Use the actual config directory, with no symlink in its path. Rebuild the archive from the toolkit instead of manually editing it. The installer refuses unsafe paths, links, duplicate members, incomplete assets, and oversized packages. Use --replace only for an intentional update; use the Samba route if direct local access is unavailable.

I do not see 3D Home, or an entity will not respond

Confirm the folder is exactly custom_components/home_floorplan, check the YAML entry, and check HA logs for home_floorplan. Restart after a successful configuration check and sign in as an administrator. For device controls, verify the entity ID and availability in HA, then wait for the layout to save.

The same core can serve a private project

The public package is MIT licensed. A private project can use its compiler, viewer, integration core, and installer while keeping its plans and extra adapters private. Generic packages require site.json with site_features: false.

Separately supplied private_site and private_site_config modules can support a household's custom behavior. Installing such a prepared private package requires --allow-site-features; that flag does not add missing modules, set up SSO, or discover devices. See the shared-core architecture for details.
